Westarctica Network Information Center

A common name for the
Westarctican network

The Network Information Center maintains a shared domain namespace for Westarctican institutions, offices, and individuals. As a service of the Westarctican College of Arms, it emphasizes enduring institutional identities and a publicly reviewable record.

Registry in preparation. Public registrations are not yet open. HTTPS website forwarding is operational in a limited pilot. The instructions below explain how to prepare a request; general DNS publication and email forwarding are not yet available.

Registration Guide

Prepare a request for a name beneath westarctica.net

Public applications not yet open

WNIC is testing a manually reviewed website-forwarding service. You can prepare your registration using this guide, but please wait for the opening announcement before submitting a public application. The draft registration policy remains under review.

Choose the service you need

Website forwarding

Operational pilot. Give an existing website a Westarctican address. Visitors are redirected to your existing URL, which becomes the address shown in their browser. You keep your current hosting provider.

Example: krigsvold.westarctica.net forwards to krigsvold.org.

DNS records or delegation

Publication under development. For a website that stays at the Westarctican address, your host must accept that custom hostname and provide HTTPS. A CNAME alone does not do this. NS delegation lets your DNS provider administer an assigned subdomain.

The registry can validate DNS requests, but general automated DNS publication has not opened.

Email forwarding

Not yet available. An address such as yourname@westarctica.net would forward incoming mail to a verified mailbox. A domain-name request does not create an email address.

Do not submit your private destination email address in GitHub.

Prepare a website-forwarding request

  1. Choose a name. Use the ledger checker above. Enter only the part before .westarctica.net: 1–63 lowercase letters, digits, or single hyphens, beginning and ending with a letter or digit. Consecutive hyphens are not accepted. A name absent from the ledger is not reserved for you or guaranteed to be approved.
  2. Choose your destination. Supply the full public HTTPS URL of a website you control or are authorized to represent. Forwarding changes the browser address; it does not host a copy of the destination site.
  3. Prepare your registration file. Using a GitHub account, fork the public registry repository. Add domains/yourname.json, replacing yourname in the filename with your chosen name. Copy the example below, then replace the GitHub username and destination URL.
  4. Check and submit when applications open. Review the registration policy, then open a pull request from your fork to westarctica/nic. Explain whom the name represents and confirm your authority to use the destination. Automated checks validate the file; a maintainer reviews the request. A passing check is not approval.
  5. Wait for publication. An approved request is merged into the ledger and the forwarding publisher runs separately. A merged entry is not proof of activation: wait for successful publication, then test your new address over HTTPS.

Example · domains/yourname.json

{
  "owner": { "username": "YOUR-GITHUB-USERNAME" },
  "service": {
    "type": "redirect",
    "target": "https://example.org",
    "status": 301,
    "preservePath": true,
    "preserveQuery": true
  }
}

This requests a permanent (301) redirect. With both preservation options enabled, yourname.westarctica.net/news?year=2026 forwards to example.org/news?year=2026. Use false for either option if you do not want that behavior. Permanent redirects may be cached by browsers.

Review, privacy, and later changes

Registration files, pull requests, and their history are public. Include only the information needed for the request. Never publish passwords, API tokens, identity documents, private email addresses, or other confidential evidence.

Names associated with Westarctica are subject to review for eligibility, reserved institutional use, confusion, impersonation, and abuse. Institutional names remain with the office or institution when its administrator changes. Assignments are subdomains, not ownership of the parent domain or ICANN-accredited registrations.

For a destination change, transfer, or withdrawal during the pilot, open an issue in the registry repository describing the requested change without private information. A maintainer must review and arrange publication; editing or deleting a JSON file alone does not update or remove the live service.

The Registry

Designed to begin simply, and to endure

I

Public records

Approved assignments will be recorded in a public, versioned registry, with changes reviewed through GitHub.

II

Independent operation

The registry supports requests for delegation to an independent DNS provider. General DNS publication remains under development.

III

Continuity of office

Addresses assigned to institutions follow their offices through changes of leadership and administration.
